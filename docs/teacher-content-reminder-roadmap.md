# 教师内容提醒系统实施拆解

## 1. 实施原则

- 先跑通闭环，再逐步提质量
- 先半自动，再全自动
- 先少来源高质量，再扩来源
- 先单模板稳定，再扩多模板

## 2. 建议迭代路线

## 阶段 0：方案冻结

目标：

- 锁定来源范围
- 锁定内容模板
- 锁定题型范围
- 锁定难度档位

交付物：

- PRD
- 技术设计
- 示例配置

## 阶段 1：内容抓取闭环

目标：

- 能定时抓到文章
- 能正确抽正文
- 能做去重和筛选

任务拆解：

- 建项目骨架
- 定义配置结构
- 实现来源管理
- 实现 RSS 抓取器
- 实现 HTML 栏目页抓取器
- 实现正文提取器
- 实现文章入库
- 实现 URL 去重和内容哈希去重
- 实现基础日志

完成标准：

- 每天能稳定抓取候选文章
- 人工验证正文提取质量可接受

## 阶段 2：AI 生成闭环

目标：

- 文章可以稳定生成教学内容包

任务拆解：

- 设计统一文章输入结构
- 实现事实提取 Prompt
- 实现价值评分模块
- 实现标题和摘要生成
- 实现阅读短文改写
- 实现阅读理解生成
- 实现完形填空生成
- 实现答案与解析生成
- 实现生成结果结构校验

完成标准：

- 生成结果格式稳定
- 题目和正文基本匹配
- 可供人工审核

## 阶段 3：审核与推送闭环

目标：

- 支持预览、审核、钉钉发送

任务拆解：

- 定义推送模板
- 实现内容预览页或预览接口
- 实现审核状态机
- 实现钉钉消息渲染
- 实现 webhook 推送
- 实现投递日志与失败重试

完成标准：

- 审核通过内容可成功发到钉钉
- 出错可定位、可重试

## 阶段 4：质量优化

目标：

- 提高内容命中率和可直接使用率

任务拆解：

- 增加多来源打分策略
- 做相似主题聚类
- 增加关键词和学段偏好配置
- 优化题目难度控制
- 增加教学建议模块
- 增加敏感内容过滤

## 阶段 5：运营与扩展

目标：

- 从工具走向可运营系统

任务拆解：

- 多模板管理
- 多群分发
- 用户偏好配置
- 反馈数据回流
- AI 配图
- 多语言支持

## 3. MVP 任务清单

建议我们实际开发时按以下顺序推进：

1. 项目初始化
2. 配置模型定义
3. 来源抓取器
4. 正文提取器
5. 去重与入库
6. 候选内容筛选
7. LLM 接口封装
8. 摘要与标题生成
9. 阅读材料生成
10. 题目与答案生成
11. 钉钉消息模板
12. 审核与发送

## 4. 推荐优先级

### P0

- 来源配置
- 定时抓取
- 正文提取
- 去重
- 标题和摘要生成
- 阅读理解
- 钉钉推送

### P1

- 完形填空
- 教学价值点评
- 难度调节参数
- 人工审核页面

### P2

- 相似主题聚类
- AI 配图
- 多租户
- 数据反馈闭环

## 5. 关键配置项建议

建议把以下能力做成配置，而不要写死在代码里：

- 来源启停
- 来源优先级
- 每日最大推送数
- 各主题占比
- 目标人群
- 难度档位
- 题型组合
- 推送时段
- 审核模式
- 价值分阈值

## 6. 示例工作流

### 工作流 A：每日晨读

- 06:30 抓取
- 06:40 生成候选内容
- 06:50 人工审核
- 07:30 推送到钉钉

### 工作流 B：自动内容池

- 每小时抓取一次
- 自动筛选高分内容
- 入候选池
- 到固定时间统一推送

## 7. 风险拆解

### 技术风险

- 某些站点解析不稳定
- LLM 生成结构不稳定
- 钉钉消息格式受限

### 业务风险

- 内容虽新但不适合教学
- 题目可用性不高
- 难度分层不准

### 应对策略

- 来源分层接入
- Prompt 分步生成
- 增加结构校验
- 先人工审核

## 8. 下一步建议

建议下一轮直接进入工程落地：

1. 先初始化后端项目骨架
2. 做来源配置和抓取模块
3. 跑通“抓取 -> 提取 -> 入库 -> 预览”
4. 再接 LLM 生成和钉钉推送
